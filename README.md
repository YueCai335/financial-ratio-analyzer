# Financial Ratio Analyzer

Enter key financial statement data for a few companies, automatically compute eight core financial ratios, and view multi-year trends and cross-company comparisons in charts.

## Running it

```bash
cd backend
.venv/bin/python seed.py                          # load sample data (drops and rebuilds)
.venv/bin/python -m uvicorn app.main:app --reload  # start the server
```

Open http://127.0.0.1:8000 — the frontend is served by the backend, no separate server needed.
API docs are at http://127.0.0.1:8000/docs (auto-generated by FastAPI).

Run the tests:

```bash
cd backend && .venv/bin/python -m pytest test_ratios.py -v
```

## The eight ratios

| Ratio | Formula | What it shows |
|------|------|--------|
| Gross Margin | (Revenue − COGS) / Revenue | Pricing power and cost structure |
| Net Margin | Net Income / Revenue | Share of revenue that reaches the bottom line |
| ROE | Net Income / Total Equity | Return on shareholders' capital |
| ROA | Net Income / Total Assets | Asset efficiency, independent of leverage |
| Current Ratio | Current Assets / Current Liabilities | Short-term solvency |
| Quick Ratio | (Current Assets − Inventory) / Current Liabilities | Short-term solvency excluding the hardest asset to liquidate |
| Debt to Assets | Total Liabilities / Total Assets | Share of assets funded by debt |
| Equity Multiplier | Total Assets / Total Equity | Leverage multiple |

Two identities are asserted in the tests, so a wrong formula gets caught:

- `ROE = ROA × Equity Multiplier` (DuPont analysis)
- `Equity Multiplier = 1 / (1 − Debt to Assets)`

## Structure

```
backend/
  app/
    database.py   SQLite connection, session, base class
    models.py     Two tables: Company / FinancialStatement
    schemas.py    Pydantic: API input/output shapes
    ratios.py     Eight ratio formulas as pure functions (no database dependency)
    health.py     Health-check threshold rules (fixed, explainable)
    main.py       FastAPI routes + serves the frontend
  seed.py         Sample data
  test_ratios.py  Tests for the ratio calculations
frontend/
  index.html      Single-file frontend, charts via Chart.js
```

## A few technical choices

**Why SQLite instead of PostgreSQL.** Single file, no Docker, no separate database server to run. This project's data volume (a few dozen records) and concurrency needs (single user) never come close to needing what PostgreSQL offers. The trade-off — weaker concurrent writes, looser type checking — doesn't matter here.

**Why amounts use Float instead of Numeric.** Floats have rounding error (`0.1 + 0.2 != 0.3`), which is unacceptable in a real accounting ledger. Here they only feed ratio math and charts, where the error is many decimal places out and never changes a conclusion. Known trade-off, judged not to matter in this context.

**Why ratios.py doesn't import the database.** Plain numbers in, plain numbers out. This lets it be tested in isolation from the database (`test_ratios.py` runs in 0.02 seconds), and a future database swap wouldn't require touching the calculation logic. All the translation work is concentrated in one function, `_to_fields()` in `main.py`.

**Why an unavailable ratio returns None instead of 0.** "Cannot be computed" and "computes to zero" are different things. When equity is 0, ROE is meaningless, not zero. Returning None lets the frontend show "—" instead of a misleading number.

## Known limitations

- **Health-check thresholds aren't industry-specific.** A current ratio below 1 is normal for retail (riding supplier payment terms is the business model), but a warning sign for manufacturing. A rigorous version would compare against the industry median — out of scope for this MVP.
- **Fiscal years aren't aligned across companies.** Apple's fiscal year ends in late September, Microsoft's in late June, Walmart's in late January, so the same `fiscal_year` value doesn't cover the same calendar period — worth keeping in mind for comparisons.
- **Sample data hasn't been verified line-by-line.** The numbers in `seed.py` are drawn from each company's 10-K but haven't been checked against the source figure by figure. Use them to demo the charts and calculations, not as an analysis basis.
- **Deliberately not included**: real-time stock price APIs, any predictive or investment-advice logic, user login/accounts.
